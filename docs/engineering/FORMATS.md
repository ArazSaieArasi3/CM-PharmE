# CM-PharmE Ontology Formats

CM-PharmE uses one authoritative semantic source and multiple generated consumer views. The authoritative authoring source is modular Turtle under `ontology/source/modules/`; generated formats are never edited independently.

| Format | File | Purpose | Semantic rule |
|---|---|---|---|
| Turtle | `cm-pharme.ttl` | Authoring-friendly consolidated RDF view | Must match the canonical graph |
| OWL / RDF-XML | `cm-pharme.owl` | Standard OWL distribution for ontology tools/reasoners | Same canonical graph |
| RDF/XML | `cm-pharme.rdf` | RDF/XML compatibility | Same canonical graph |
| Expanded JSON-LD | `cm-pharme.jsonld` | Complete JSON-LD graph view | Same canonical graph |
| Compacted JSON-LD | `cm-pharme.compact.jsonld` | Application-facing JSON-LD | Same canonical graph |
| JSON-LD context | `cm-pharme.context.json` | Stable compact IRI/prefix context | Namespace view, not an independent ontology |
| N-Triples | `cm-pharme.nt` | Canonical line-oriented RDF and fingerprinting | Same canonical graph |
| TriG | `cm-pharme.trig` | Dataset-capable RDF syntax; current file uses the default graph | Union graph equals canonical graph |
| N-Quads | `cm-pharme.nq` | Dataset-capable line syntax; current file uses the default graph | Union graph equals canonical graph |
| Manchester | `cm-pharme.omn` | Human-readable OWL review/debugging | Generated by ROBOT/OWLAPI and round-trip checked |
| OWL Functional | `cm-pharme.ofn` | Axiom-oriented formal review/diff | Generated by ROBOT/OWLAPI and round-trip checked |
| SHACL | `cm-pharme.shacl.ttl` | Structural/cardinality shapes | Generated from active relation metadata |

## Why multiple formats?

Different tools consume different syntaxes. The repository therefore provides several views while preserving one source of truth. RDF-compatible views are checked for graph equivalence. Manchester and Functional Syntax are generated through ROBOT and converted back to RDF/OWL during CI for round-trip comparison.

## Named-graph boundary

TriG and N-Quads are currently default-graph views. They are included to support future provenance- or evidence-oriented datasets without prematurely assigning named-graph semantics. A future version may define explicit named graphs for core ontology, provenance, mappings, datasets, and evidence.
