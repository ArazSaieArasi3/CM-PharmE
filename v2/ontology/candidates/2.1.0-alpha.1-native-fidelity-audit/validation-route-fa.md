# مسیر اعتبارسنجیِ پیشنهادی با حفظ معنا

وضعیت: بخش حفظ داده اجرا شده؛ مسیر کاملِ معنایی هنوز مصوب یا تکمیل نشده است. PR305 پیش‌نویس می‌ماند.

| لایه | کار انجام‌شده | شرطی که هنوز لازم است |
|---|---|---|
| مرجع بومی | ورودی اصلی ۶۵۶ عنصر حفظ شد؛ schema/parser رسمی اجرا شد. | عبور از schema دلیل درستی معنا نیست. |
| حفظ اطلاعات | ۱۳ Event، دو Situation، ۱۴۷ مقدار nature، ۲۵ متن Note، نوع/کاردینالیتی و ارجاع‌های تخصص بدون تغییر در خروجی خام باقی ماندند. | ۸۲ `isReadOnly:null` در parser به false تبدیل می‌شود؛ نتیجهٔ تحلیل زمانی باید از JSON اصلی یا خروجی نگهبانی‌شده خوانده شود. |
| نگهبان صادرات | اختلاف‌ها ثبت شد؛ بازسازی کنترل‌شده با رجوع به اصل ورودی، برابریِ مقدارهای JSON را به دست داد؛ ۱۰ تغییر نامجاز رد شد. | این wrapper کتابخانهٔ رسمی را اصلاح نمی‌کند. شیء درون‌حافظه‌ای parser همچنان boolean پیش‌فرض دارد. |
| قواعد محدود بومی | هر ۱۴ subsetting از نظر ارجاع، نوع، زمینه، سقف و نام بررسی شد؛ ۲۱ شاهد کنترل قواعد اجرا شد. | هر ۱۴ ردیف در مجموع UNKNOWN است؛ قواعد کامل UML و معنای رخداد، وضعیت و nature اجرا نشده‌اند. |
| تطابق OWL | جهت و نوع دو سر و subPropertyOf برای هفت رابطه برابر است. | این بررسی، برابری کاردینالیتی و معنای کامل سه نمایش نیست؛ دو aboutness آزمایشیِ قبلی نیز همچنان نیازمند هم‌ترازی‌اند. |
| موتور آرشیوی | حساسیت پایهٔ ۲۰ خانواده در بستهٔ قبلی موجود است؛ این اجرا هفت قطعهٔ واقعی را به‌درستی رد کرد. | تبدیل کامل ۱۵ Event/Situation، ۱۴۷ nature، یادداشت‌ها، ۱۱ سر بی‌نوع، ۶۶ کاردینالیتی نامشخص، ۸۲ readOnly نامشخص و سیاست ۷۹ stereotype رابطهٔ خالی حل نشده است. شمارش‌ها همپوشانی دارند. |
| اعتبارسنجی دامنه | آزمون‌های محدود OWL/SHACL/CQ بسته‌های چهار دامنه و هویت محتوا قبلاً اجرا شده‌اند و فایل‌هایشان تغییر نکرده‌اند. | هویت رخدادها/وضعیت‌ها، مشارکت و زمان، تحلیلِ تمام الگوهای مرتبط، دادهٔ مستقل و ارزیابی انسانی هنوز باید تکمیل شوند. |

نباید محدودیت موتور قدیمی را با تبدیل Event یا Situation به Kind، حذف nature، حذف Note یا پرکردن null رفع کرد. مسیر پیشنهادی ترکیبی است: بررسی‌های بومی روی مرجع کامل، قواعد معناییِ مشخص و آزمون‌دار برای ویژگی‌های جدید، و موتور آرشیوی فقط در زیرمجموعه‌ای که دامنهٔ اعتبار آن گزارش شده است. پذیرش این ترکیب به‌عنوان جایگزینِ «اجرای کامل ۲۰ خانواده روی کل مدل» یک **تصمیم روش‌شناختی باز** است؛ فعلاً آن معیار بسته نشده و اجرای کامل همچنان ۰/۲۰ است.

## اثر بر #315 و پیشنهاد سیاست منابع

چهار اختلاف قبلی RelComp، WholeOver، RelRig و HomoFunc پابرجاست. پیشنهاد مشخص برای بررسی: یک profile نسخه‌دار `CMPE-source-review-v1` شامل وضعیت منبع، خروجی موتور، نظرِ مبتنی بر منبع، و تصمیم نویسنده؛ موتور اصلی و oracleهای مشاهده‌شده تغییر نکنند. تا زمان تصویب، نتیجهٔ این چهار خانواده دارای برچسب «نیازمند داوری منبع» باشد و برای بستن gate استفاده نشود. این پیشنهاد profile اجراییِ جایگزین یا پذیرش علمی نیست.

| خانواده | تصمیمی که باید ثبت شود | معیار منفی پذیرش |
|---|---|---|
| RelComp | نقش کفِ مثبت در شرط تشخیص؛ منبع حاکم و نسخهٔ آن. | نادیده‌گرفتن شاهدِ کف صفر یا تغییر oracle برای سبزشدن. |
| WholeOver | انتخاب آگاهانهٔ مرز جمع سقف ۲ یا ۳ با توجیه. | حذف حالت مرزی ۲ از شواهد. |
| RelRig | تعیین سرِ رابطه و جهت شرط readOnly بر اساس معنای وابستگی زمانی. | قضاوت دربارهٔ readonly نامشخص از روی false تولیدشده توسط parser؛ یا یکی‌گرفتن کاردینالیتی با هویت ثابت مشارکت‌کننده. |
| HomoFunc | تعیین نقش کف ۱ در برابر حداقل ۲. | تبدیل اختلاف نسخه/تفسیر به «نقص قطعی انتالوژی» بدون داوری. |

یافتهٔ جدیدِ ۸۲ null، اختلاف پنجم در همان چهار قاعده محسوب نمی‌شود: این یک مسئلهٔ جداگانهٔ وفاداری serialization زیر #310 است. سه mediation این گروه مجموعاً شش null دارند و اهدافشان Role هستند؛ از این شمارش نمی‌توان ۸۲ یا شش رخداد RelRig نتیجه گرفت. پروندهٔ #315 فقط این وابستگی ورودی را یادآوری می‌کند.

روش بازتولید و hash کتابخانه در گزارش JSON آمده است. نگهبان جدید آداپتور، null را رد می‌کند؛ مدل‌های آزمایشیِ قبلی که null داشتند به‌عنوان شاهدِ صرفاً ساختاری باقی می‌مانند و شاهدِ وفاداری readOnly شمرده نمی‌شوند.
