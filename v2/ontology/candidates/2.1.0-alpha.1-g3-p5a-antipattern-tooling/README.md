# G3-P5a — full-detector compatibility and bounded current-model audit

**Status:** the official 20-item anti-pattern catalogue has **not** been executed as a complete detector on the 536-element G3-P4a candidate. This package documents an executable attempt to qualify the available tools, plus reproducible bounded checks on the exact current native model. It is an evidence checkpoint, not an ontology clean-conformance certificate.

## Tested inputs and tools

The candidate is [`../g3-p4a-supply-capacity/ontouml.json`](../g3-p4a-supply-capacity/ontouml.json): 536 native elements, 144 classes including six datatypes, 86 binary relations. `probe_ontouml_js.cjs` validated it with `ontouml-schema@1.0.2` and parsed it with `ontouml-js@1.0.0` (144 classes, zero schema errors); that library has 138 public exports and no detector-like/`OntoumlVerification` export in the installed version. It does **not** provide a complete anti-pattern result.

The [current OntoUML server](https://github.com/OntoUML/ontouml-server#available-services) advertises `/v1/verify` for semantically motivated *syntactic* constraints and does not advertise a 20-pattern endpoint. The [Visual Paradigm plugin](https://github.com/OntoUML/ontouml-vp-plugin#model-verification-and-diagram-verification) also describes syntactic verification. The archived [OLED source](https://github.com/nemo-ufes/ontouml-lightweight-editor) contains the older automatic anti-pattern implementations. A temporary sparse checkout at commit `42b926f6c2859dc87e49a96b8482eae28d02e7d5` identified **21 registered detector classes** in `br.ufes.inf.nemo.antipattern/src/br/ufes/inf/nemo/antipattern/MultipleModelProcesser.java`: the 20 catalogue names (archived Java spells `MultDep` as `MultiDep`) plus `AssCyc`. This processor calls `new OntoUMLParser(fileName)` on `.refontouml` files. A bundled sample begins with `<RefOntoUML:Package ...>` in XMI. The current candidate is flat JSON, and no semantics-preserving XMI conversion has yet been built and validated. Therefore the archived engine was **inspected but not executed on the current model**.

## Actual bounded results on the current candidate

`scan_current.py` and `scan_structural.py` were executed directly on the 536-element JSON; their results are `current-prefilter.json` and `structural-results.json`. The same scripts also ran on the previous 523-element B2 native overlay (`b2-prefilter-comparison.json` and an ephemeral structural report). All comparable bounded trigger counts remained unchanged after the four P4a relations. Among current triggers: BinOver simple same/ancestor-end paths 2; ImpAbs multi-valued subtype ends 10 across six relations; RepRel direct relators 19; MixIden *preconditions* 9; RelSpec endpoint specialization pairs 3; RelComp 0 known-cardinality candidate pairs with 2 possible pairs whose A cardinality is unknown; RelOver 5 relators with potential overlap (one has an unknown upper sum). There are 33 associations with at least one unspecified end cardinality. None of those counts is a count of confirmed anti-pattern defects.

`build_coverage.py` produces `coverage-ledger.json`, mapping each of the [20 documented patterns](https://ontouml.readthedocs.io/en/latest/anti-patterns/index.html) to its archived implementation path, bounded trigger, selected native witness and editorial domain where a witness exists. All 20 rows explicitly state `NOT_EXECUTED_ON_THIS_JSON` and pending semantic review. A zero result for a narrow necessary-condition check does not establish absence of the complete pattern. The documented catalogue and archived engine are not identical sets: the archived processor registers `AssCyc` in addition to the 20 documented entries.

## Exact release gate and next executable task

G3-P5 stays **open**. To run the archived official engine faithfully: pin the archived Java/EMF runtime; build OntoUML 1.0.2 JSON → RefOntoUML XMI conversion with stable element IDs and explicit mapping of class stereotypes/natures, generalizations and sets, association stereotypes, ends, multiplicities, subsetting and derivation; round-trip/check the generated EMF model and run positive/negative toy models for all 20 pattern detectors. Only then batch-run the 536-element candidate, keep raw detector outputs, map each actual occurrence to native IDs and domains, and obtain scientific dispositions. An alternative compatible official detector with equivalent full coverage may replace this adapter if verified. The current native model, PR #305, and G3 stage status are unchanged by this tooling audit.
