# گام دوم نمونه‌های چهار دامنه: رفع شکاف‌های مشخص

تاریخ: ۲۰۲۶-۱۰-۰۹؛ وضعیت: **آزمایش محدود، آمادهٔ داوری معنایی**. خروج یا انتقال چهار دامنه همچنان معلق است. مدل مبنا و تمام فایل‌های آزمایش قبلی حفظ شده‌اند.

## دستاورد این اجرا

| اصلاح | نتیجهٔ پیاده‌سازی | حد باقی‌مانده |
|---|---|---|
| زمینهٔ ریسک | سناریوی محصول، تأسیسات یا وابستگی عرضه پذیرفته می‌شود؛ ساخت محصول فرضی اجباری نیست | هویت نسخه‌های ارزیابی و پوشش کامل انواع ریسک باز است |
| حامل گزارش و ادعا | دو حامل می‌توانند یک ادعای تصریح‌شده را حمل کنند؛ شناسهٔ پروندهٔ ثابت، ادعاهای تغییرکرده را ادغام نمی‌کند | Assertion نمایندهٔ یک گزاره است؛ کل محتوای ICSR یا گزارش را مدل نکرده‌ایم |
| مسئول ارزیابی سیگنال | سازمان ارزیاب همراه زمان و وضعیت نتیجه بازیابی می‌شود | سازمان ارزیاب الزاماً نهاد مقررات‌گذار نیست؛ اشخاص و تفویض اختیار کامل نشده‌اند |
| زمینهٔ خدمت | مشخصات خدمت به محصول یا تأسیسات و قابلیت متصل است | همهٔ انواع خدمت و معنای تعهد ارائهٔ خدمت پوشش داده نشده است |
| شاهد تعهد همکاری | توافق به گزارهٔ تعهد و طرف‌ها وصل است؛ EvidenceSupport موجود، منبع را قابل بازیابی می‌کند | حضور شاهد به معنی صحت مستقل تعهد یا اعتبار قانونی آن نیست |
| فعالیت دیجیتال در زمینهٔ دارویی | تبدیل داده به رخداد ساخت دارو، محصول و تأسیسات متصل است؛ جزء سامانه با استقرار سازگار می‌ماند | رابط فعلی به ManufacturingActivity محدود است |
| مسئولیت فعالیت | مسئول تبدیل داده می‌تواند با سازمان استقرار فرق داشته باشد | هویت همهٔ عامل‌ها و تفویض مسئولیت کامل نشده است |
| منبع پایش | رابطهٔ surveillanceSource اکنون نیازمندی صریح و آزمون مثبت/منفی دارد | منبع به‌تنهایی علیت یا انطباق با مقررات را ثابت نمی‌کند |

این هشت مورد، ریزکردن شکاف‌های ۲۴ نیازمندی قبلی‌اند؛ پذیرش علمی یا هشت نیازمندی مستقلِ مورد تأیید نویسنده تلقی نمی‌شوند. **کلاس جدید: صفر؛ رابطهٔ آزمایشی اضافی: ۱۲.** تعداد تصمیم‌های باز دربارهٔ روابط آزمایشی اکنون ۳۹ است.

## نتیجهٔ اجرا

- **۳۷/۳۷** آزمون SHACL جدید مطابق انتظار، شامل نمونهٔ ترکیبی.
- **۳۹/۳۹** آزمون SHACL قبلی با قواعد جدید دوباره اجرا و مطابق انتظار شد.
- **۸/۸** پرسش جدید با پاسخ ثابت؛ **۸/۸** آزمون HermiT مطابق انتظار.
- schema و parser رسمی native قبول: ۶۵۶ عنصر، ۱۴۷ رکورد Class شامل ۱۴۱ کلاس نام‌دار و ۶ datatype.
- نمونهٔ واقعی قبلی، ۷۶۸ ردیف و ۳۹٬۲۷۲ سه‌تایی، همچنان سازگار و منطبق است؛ نمونهٔ پروفایل‌های جدید ندارد و فقط آزمون بازگشت است.
- آزمون‌های مدل خلاف نشان می‌دهند یک شناسهٔ پرونده می‌تواند با دو حامل/ادعای متمایز سازگار باشد؛ تماس اتفاقی الزاماً نقش شریک نمی‌سازد؛ ارزیاب الزاماً نهاد مقررات‌گذار نیست؛ مسئول فعالیت می‌تواند با سازمان استقرار فرق کند.

قواعد پروفایل SHACL قرارداد پذیرش داده‌اند. این‌ها جای اصل هویت UFO، داوری متخصص یا تطابق کامل native/OWL/SHACL را نمی‌گیرند. انتظارات اولیه در `contracts.json` و نتایج واقعی در فایل‌های نتایج ثبت شده‌اند.

## تحلیل روابط و مسائل حل‌نشده

برای هر **۳۹ رابطهٔ آزمایشی**، مبدأ/مقصد، نیازمندی، خانوادهٔ معنایی، دلیل و اقدام پیشنهادی در `relation-semantic-review.json` ثبت شد. به‌ویژه رابطهٔ استناد، مستندکردن توافق یا ارتباط رخداد را صرفاً برای پرکردن stereotype، «formal» یا «mediation» اعلام نکردیم. مستند OntoUML، formal مقایسه‌ای را از mediation مبتنی بر relator متمایز می‌کند؛ این قواعد به‌تنهایی برچسب درست همهٔ روابط محتوایی و رخدادی این پروژه را تعیین نمی‌کنند.

پیش‌فیلتر ساختاری هنوز **۳ نامزد BinOver**، **۱۹ نامزد RepRel** و اکنون **۴۱ پرسش ImpAbs** دارد. رشد ImpAbs با روابط و کران‌های آزمایشی مرتبط است؛ نتایج قبولی SHACL آن را برطرف نمی‌کند. اجرای رسمی ۲۰ آشکارساز هنوز انجام نشده است. هم‌ترازی بازنمایی، پروفایل‌های محتوایی، کران‌های عمومی و adapter رخدادها گام بعدی‌اند.

## قرارداد منبع و برنامهٔ باز

در همین اجرا، مسئلهٔ #307 نیز جلو رفت: نام واقعی فایل P1 در manifest تثبیت شد؛ نام نمونهٔ مصنوعی جدا شد؛ ۱۲ آزمون منفی قرارداد و بازاجرای تبدیل ۷۶۸ ردیف موفق شدند. CI در GitHub پیش از ثبت هر گام اجرایی ناموفق شد و لاگ قابل بازیابی نداشت؛ علت دقیق روشن نیست. PostgreSQL/PostGIS در محیط محلی موجود نبود و تلاش نصب با خطای مجوز محیط متوقف شد. بنابراین نتیجهٔ اجرای کامل پایگاه‌داده به‌دست نیامد و #307 باز ماند. شواهد و محدودیت‌ها در `v2/data/sources/p1-contract-2026-10-09/` هستند.

برنامهٔ اصلی **۲۳ کار** در `continuation-checkpoint.json` حفظ شده است. هیچ پذیرش علمی خودکاری از این اجرا نتیجه نشده است. وضعیت تاریخی دروازه‌ها **۲/۵ = ۴۰٪** و زیرگام‌های بستهٔ G3 **۲/۷ = ۲۸٫۶٪** باقی است. پوشش اجرای این بسته **۸/۸ = ۱۰۰٪** است و درصد تکمیل کل انتالوژی نیست.

گام مستقیم بعدی: نتیجهٔ CI قرارداد منبع را بررسی کنیم؛ سپس هویت محتوای اطلاعاتی و روابط رخدادها را برای تصمیم P3/P5 و هم‌ترازی سه نمایش آماده کنیم. دامنه‌های چهارگانه، #306 و PR #305 در وضعیت بررسی می‌مانند.

## بازتولید

با وابستگی‌های Python و Java بستهٔ آزمایش قبلی، از ریشهٔ مخزن:

```bash
python v2/ontology/candidates/2.1.0-alpha.1-four-domain-refinement/build_refinement.py
python v2/ontology/candidates/2.1.0-alpha.1-four-domain-refinement/run_refinement.py
python v2/ontology/candidates/2.1.0-alpha.1-four-domain-refinement/finalize_refinement.py
```

`contracts.json` منابع و حد استناد آن‌ها را دارد. منابع اصلی اضافه‌شده: ICH E2B(R3) بخش C.1.1/C.1.8.1، EMA GVP IX، W3C PROV-O بخش ۳.۱ و مستندهای رسمی روابط OntoUML. نگاشت پیشنهادی این پروژه از خود این استانداردها نتیجهٔ قطعی نشده است.
