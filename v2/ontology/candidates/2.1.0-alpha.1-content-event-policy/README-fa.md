# CM-PharmE v2.1 — سیاست هویت محتوا و آزمون آشکارسازها

این بسته ادامهٔ مستقل آزمایش چهار دامنه است. مبنا و دو آزمایش قبلی تغییر نکرده‌اند. تصمیم خروج یا انتقال Risk Management، Pharmacovigilance، Business Architecture و Digital Systems نهایی نشده است.

**دستاورد:** یک شکاف هویت کشف شد؛ دو قاعدهٔ محدود پیشنهادی آزموده شد؛ اجرای واقعی هر ۲۰ آشکارساز آرشیوی روی مدل تاریخی موفق بود و دو خانوادهٔ دیگر نمونه‌های مثبت/منفی گرفتند.

## هویت و روابط

`identity-decisions.json` شامل ۹ پیشنهاد و `relation-decision-cards.json` شامل ۳۹ کارت تصمیم است. ۲۰ کارت تفسیر ویژهٔ رخداد یا تحقق قابلیت دارند. نتیجهٔ ارزیابی باید از سیگنال هدف خودش، و حامل باید از گزاره‌ای که حمل می‌کند، جدا باشد. شناسهٔ یکسان پرونده یا متن یکسان دلیل یگانگی حامل‌ها و گزاره‌ها نیست.

آزمون اولیه نشان داد `carrierClaim(record, record)` در OWL قبلی سازگار بود؛ `discovered-counterexample.json` این شکست را نگه می‌دارد. پیشنهاد اصلاح، دو `owl:IrreflexiveProperty` و دو شکل SHACL بر اساس استفاده از خود رابطه است. حذف برچسب profile این دو کنترل را غیرفعال نمی‌کند. مسیرهای صریح چندمرحله‌ای `owl:sameAs` نیز بررسی می‌شوند؛ این معادل استنتاج تمام شکل‌های ممکن برابری OWL در SHACL نیست.

هیچ کلاس/رابطهٔ جدید، تمایز جهانی SourceRecord/Assertion، تقارن‌ناپذیری جهانی، تعدی یا stereotype تازه‌ای اعمال نشده است. بازاستفادهٔ محتوا در زمینه‌های مختلف همچنان ممکن است؛ این امکان منطقی به معنی تأیید هر چرخهٔ واقعی نیست. هویت کامل محتوای گزارش، انطباق کامل ICSR، معنای جهانی رخداد و کران‌های نهایی هنوز بازند. قواعد جغرافیایی قبلی حفظ شده‌اند؛ هشدار ساختاری BinOver صرفاً با افزودن قاعده ناپدید نمی‌شود.

|---|---|---|

| بازگشت SHACL قبلی | ۷۶/۷۶ | عدم تغییر پاسخ‌های شاهدهای قبلی |

| حساسیت محدود | ۸/۸ نمونه، ۳/۲۰ خانواده | BinOver، ImpAbs و RepRel؛ شش نمونهٔ جدید و دو بازاجرا |
| کل مدل فعلی در موتور آرشیوی | اجرا نشده | تبدیل عمداً رد می‌شود |

مدل تاریخی ۲۶ کلاس و ۱۸ association دارد. تعداد موارد آشکارشده در آن، عیب‌های CM-PharmE نیست. برای ۱۷ خانواده هنوز شاهد مثبت/منفی نداریم؛ اجرای بدون خطا حساسیت یا کامل‌بودن آشکارسازی را اثبات نمی‌کند.

مدل آزمایشی فعلی ۱۵ کلاس Event/Situation فاقد نگاشت، ۱۱ سر بی‌نوع، ۶۶ کران نامشخص، ۱۴ سر تخصص‌یافته، ۱۴۷ محدودیت nature و ۷۹ stereotype رابطهٔ null دارد. این گروه‌ها هم‌پوشان‌اند و جمع آن‌ها شمار خطا نیست. `full-refinement-feasibility.json` رد تبدیل مستقیم و فهرست موانع را ثبت می‌کند. تفسیرهای پیشنهادی رخداد مجوز تبدیل Event به Kind یا استفادهٔ عمومی از mediation/formal نیستند.

## بازتولید

نیازها: Python با rdflib، pyshacl و owlready2؛ Java 17؛ ECJ 3.39.0؛ بسته‌های native قبلی. آرشیو OLED باید دقیقاً در commit `42b926f6c2859dc87e49a96b8482eae28d02e7d5` باشد. ترتیب JARها و hash ورودی‌ها در گزارش‌ها ثبت شده است.

```bash
python run_policy.py
python run_catalogue.py /path/to/archived-oled /path/to/ecj-3.39.0.jar
python run_sensitivity.py /path/to/archived-oled /path/to/ecj-3.39.0.jar /path/to/node_modules
```

`run_policy.py` از دو بستهٔ قبلی با مسیر نسبی استفاده می‌کند. نتایج آزمون، پذیرش علمیِ همان نیازمندی‌ها نیستند.
