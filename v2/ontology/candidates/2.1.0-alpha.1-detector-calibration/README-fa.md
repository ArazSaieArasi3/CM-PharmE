# CM-PharmE v2.1 — کالیبراسیون پایهٔ ۲۰ خانوادهٔ ضدالگو

**دستاورد:** همهٔ ۲۰ خانواده اکنون شاهد مثبت و منفی پایه دارند. علاوه بر آن، تبدیل محدود ارجاع‌های subsetting و redefinition اجرا و آزموده شد. در این بررسی چهار اختلاف واقعی میان کد آرشیوی و قیود مستندات پیدا شد؛ پذیرش علمی موتور و مدل همچنان باز است.

## چه چیزی اجرا شد؟

| مجموعه | نتیجه | حدود ادعا |
|---|---|---|
| شاهدهای جدید ۱۷ خانواده | ۳۴/۳۴ | ورودی مستقیم legacy XMI؛ اثبات صحت مبدل جدید نیست |
| بازاجرای سه خانوادهٔ قبلی | ۸/۸ | hash ورودی‌ها با شواهد قبلی برابر است |
| پوشش خانواده‌های دارای مثبت/منفی | ۲۰/۲۰ | پوشش پایه، نه تمام شاخه‌ها یا درستی کامل موتور |
| آزمون‌های مرزی اختلاف منبع | ۸ حالت | پنج اختلاف با قرائت صریح قیود در چهار خانواده |
| تبدیل native و آزمون RelSpec | ۳/۳ | حالت بدون قید، subsetting و redefinition |
| رد ورودی نامعتبر مبدل | ۸/۸ | هدف ناموجود/نامعتبر، خودارجاعی، چرخه، کران نامشخص، سر بی‌نوع، Event و تکرار هدف |
| اجرای کل مدل فعلی | انجام نشده | strict adapter همچنان ورودی کامل را رد می‌کند |

فایل `fixture-manifest.json` یک قالب اختصاصیِ شاهدهای قدیمی است؛ این فایل native OntoUML JSON نیست. کلاس‌ها، روابط، ترتیب سرها، نوع، کران، aggregation، generalization و generalization set و subsetting پس از بارگذاری با parser رسمی با مشخصات شاهد مقایسه شدند. در چهار شاهد readOnly، خود این ویژگی نیز جداگانه پس از parsing بررسی شد. کد اصلی هیچ‌یک از آشکارسازها تغییر نکرد.

فهرست خانواده‌ها و نوع شاهد در `coverage-matrix.json`، نتیجهٔ کامل در `calibration-results.json` و hash کد رسمی در `official-source-manifest.json` است. نام MultDep در کاتالوگ با کلاس MultiDep در آرشیو نگاشت شده است.

## اختلاف‌هایی که نباید پنهان شوند

| قاعده | قید مستندات | رفتار بازتولیدشدهٔ موتور | پیامد |
|---|---|---|---|
| RelComp | کران پایین مثبت و کران بالا بیش از یک | در `0..2` نیز تشخیص می‌دهد | اختلاف شرط کران پایین |
| WholeOver | مجموع کران‌های بالا حداقل ۲ | در مجموع ۲ تشخیص نمی‌دهد؛ constructor حداقل ۳ می‌خواهد | اختلاف آستانه |
| RelRig | `isReadOnly(mediatedEnd)=true` | وقتی `isReadOnly(relatorEnd)=true` است مورد را کنار می‌گذارد | اختلاف سر مورد بررسی و مقدار منطقی |

مستندات RelRig در توصیف کلی و فرمول نیز یک سطح از جزئیات ندارند. این یافته‌ها اثبات نمی‌کنند کدام منبع صحیح است؛ جدول‌های ۴۴، ۴۶ و ۵۱ پایان‌نامهٔ اصلی Sales (۲۰۱۴) نیز بررسی و مؤید وجود اختلاف منبع شدند؛ برای داوری در [#315](https://github.com/ArazSaieArasi3/CM-PharmE/issues/315) ثبت شدند. به همین دلیل وضعیت نهایی این بسته `BASIC_CALIBRATION_COMPLETE_SOURCE_POLICY_REVIEW_REQUIRED` است.

پیشنهاد فعلی: نسخهٔ آرشیوی مرجع بازتولید باقی بماند؛ شمارش موتور و اختلاف با سیاست مستندات جدا گزارش شود. هر overlay یا اصلاح آینده نام و نسخهٔ مستقل داشته باشد. تا داوری، این چهار قاعده نباید مجوز خودکار بستن دروازهٔ انتشار بدهند.

HomoFunc نیز با تغییر کران پایین از ۱ به ۲ آزموده شد؛ گزارش مستقل آن در `homofunc-boundary-results.json` است.

## مبدل تخصص سررابطه

`adapter_specialization.py` روی کپی ورودی، ارجاع‌های تخصص‌یافته را جدا می‌کند، سایر اجزا را از مبدل محدود قبلی عبور می‌دهد و همان IDها را با نام‌های رسمی `subsettedProperty` و `redefinedProperty` در XMI برمی‌گرداند. ورودی اصلی تغییر نمی‌کند. هدف نامعتبر، خودارجاعی، چرخه و سایر موارد خارج از دامنه رد می‌شوند.

سه شاهد ابتدا از schema/parser جدید عبور کردند، سپس تبدیل و با parser رسمی قدیمی بارگذاری شدند. نوع و کران و مجموعهٔ ارجاع‌ها دقیقاً مقایسه شد. RelSpec برای رابطهٔ فاقد قید یک مورد و پس از subsetting یا redefinition صفر مورد گزارش کرد. این آزمون، اعتبار معنایی همهٔ حالت‌های UML یا ۱۴ سررابطهٔ واقعی پروژه را اثبات نمی‌کند. محدودیت nature و Event/Situation و کران‌های نامشخص پابرجاست. حتی Noteهای مدل کامل نیز باید حفظ شوند؛ حذف خاموش آن‌ها مجاز نیست.

## بازتولید

Java 17، ECJ 3.39.0 و آرشیو OLED دقیقاً در commit `42b926f6c2859dc87e49a96b8482eae28d02e7d5`؛ وابستگی‌های native از بستهٔ قبلی. نیازی به تغییر source آرشیوی نیست.

```bash
python make_fixtures.py
python run_calibration.py /path/to/archived-oled /path/to/ecj-3.39.0.jar
python run_readonly_boundary.py /path/to/archived-oled /path/to/ecj-3.39.0.jar
python run_homofunc_boundary.py /path/to/archived-oled /path/to/ecj-3.39.0.jar
python run_adapter_specialization.py /path/to/archived-oled /path/to/ecj-3.39.0.jar /path/to/node_modules
python finalize_calibration.py /path/to/archived-oled
```

اسکریپت نهایی نتایج و hash شاهدهای قبلی را بررسی می‌کند. موفقیت آن به معنی بسته‌شدن علمی #315 یا اجرای کل ontology نیست. prefixهای XMI هنگام بازنویسی XML حفظ می‌شوند؛ parser آرشیوی نسبت به آن‌ها حساس است.
