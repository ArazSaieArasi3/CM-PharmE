## Small-packet and decision convention

One active execution, at most three ready children. After 2–4 accepted packets,
review the smallest eligible release cut; do not manufacture a version just to
show activity. Known approval persists. Surface a short recommended-option /
benefit / cost table early for a genuinely new decision. If a packet expands,
checkpoint and split before continuing. Each user update briefly states current
target version, objective, issue and result/next release point.

Use MAJOR.MINOR.PATCH against an explicit public contract. Maturity alone is not
a major change; additive triples alone are not proof of compatibility. Keep
2.1.x fixes, 2.2/2.3 compatible capability increments, justified incompatible 3.0
and optional 4.0 horizons. No guaranteed date or execution count is recorded.
